**019**: Semantic-version release tags MUST be cut automatically from qualifying merges to `main` — no manual release step, and no separate release branch or release PR to batch them.

Rationale: the PR-review-plus-CI gate every merge to `main` already passes through (rules 014–017, 001) *is* the deliberate checkpoint — re-gating on top of it via a batched release step would duplicate a decision already made at merge time. Release tags exist for a different consumer: self-hosters (including the maintainer's own instance, if ever run outside Vercel) who have no equivalent of "the maintainer just reviewed this," and so need a stable, known-good version to pin to instead of tracking `main` HEAD. See rule 003 for the obligation that this tooling exists at all.
